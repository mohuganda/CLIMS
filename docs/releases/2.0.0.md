# CLIMS 2.0.0

Version 2.0.0 marks the revamp of the existing CLIMS project into a PostgreSQL-backed API with web and mobile foundations and a shared release process.

## Included in this release

- PostgreSQL 16 schema migrations and reproducible conversion of the legacy MySQL backup, with legacy roles and data compatibility checks.
- Backend auth, users, and RBAC modules supporting registration, login, JWT authentication, account administration, and permission checks using existing CLIMS roles.
- Swagger UI and OpenAPI documentation, with setup, architecture, database, client, and deployment guides in the root `docs/` folder.
- Next.js frontend and Expo/React Native mobile scaffolds with API readiness checks.
- Nginx routing and separate development/production Dockerfiles and Compose configurations.
- Pull request/main CI for formatting, lint, types, tests, PostgreSQL integration, and client builds.
- Versioned backend, frontend, and mobile images published to GHCR, with digest-pinned release manifests and shared application version validation.
- `make migrate-create NAME=description` for creating SQL up/down pairs using the pinned golang-migrate CLI.

## Release scope

Backend, frontend, and mobile share application version `2.0.0`; release images use the tag `v2.0.0`. API routes use `/api/v1`. PostgreSQL and Nginx remain infrastructure services built separately from the application release images.

The web and mobile projects provide the initial workspace and connection checks. Login, registration, and user-management screens are future client work. The mobile image exports JavaScript bundles and assets; native signing and application store distribution are separate workflows.

This release temporarily embeds `https://your-domain/api/v1` as the mobile API URL, as selected during release preparation. Configure the real reachable endpoint and rebuild before using mobile API connectivity. Local Compose and host development can configure their own API URL.

## Installation and upgrades

Use the [environment guide](../environments.md) for local builds and the [image release guide](../releases.md#run-published-images) for digest-pinned deployments. Download `images.json` and `images.env` from the GitHub Release to identify the exact application images.

The API applies embedded migrations at startup. Existing PostgreSQL installations retain their named data volume; legacy MySQL installations follow the [PostgreSQL conversion/import guide](../postgresql.md). Legacy seed import is a separate one-time operation on an empty migrated database. Read the [migration guide](../migrations.md) before creating or applying schema changes.
